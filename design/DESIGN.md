# Probe QA — 디자인 가이드 (구현·확장용)

이 문서는 Probe QA 화면을 **구현하거나 새 화면을 추가하는 코딩 에이전트(Codex 등)와 개발자가 반드시 따라야 하는 규칙**이다.
`screens/`의 16개 HTML/PNG는 **정답 레퍼런스**다. 새 화면을 그릴 때는 가장 비슷한 레퍼런스 화면을 열어 구조와 값을 그대로 가져온 뒤 내용만 바꾼다. 여기 없는 값(색, 크기, 라운드, 간격)은 만들지 않는다.

- 토큰 원본: `tokens.css` (CSS 변수). 색·타이포·라운드·간격은 이 파일 밖의 값을 쓰지 않는다.
- 폰트 파일: `fonts/` (Pretendard 400/500/600, JetBrains Mono 400/500). 프로젝트에 그대로 포함해 `@font-face`로 로드한다. Google Fonts 등 외부 CDN에 의존하지 않는다.
- 레퍼런스 화면: `screens/M00 … M12` 16장 (아래 §7 목록).

---

## 1. 톤 한 줄 요약

**흑백 모노톤, 장식 없음, 요소마다 한 가지 역할.** 컬러는 검정과 회색 5단계만 쓴다. 상태(성공/실패)도 색이 아니라 **글리프 + 굵기**로 표현한다. 섀도우·그라데이션·아이콘 박스·컬러 배지·왼쪽 컬러 보더·이모지는 쓰지 않는다.

레퍼런스 톤: shadcn/ui 문서, v0 진입 화면, Linear·Vercel 대시보드. "랜딩 페이지"가 아니라 "매일 쓰는 도구"다.

## 2. 컬러 (변수명은 tokens.css 기준)

| 변수 | 값 | 용도 |
|---|---|---|
| `--ink` | `#0A0A0A` | 본문 텍스트, primary 버튼 채움, 활성 글리프, 강조 보더 |
| `--text-2` | `#525252` | 설명 문장, 표 본문 |
| `--text-3` | `#737373` | 라벨, 비활성 네비, 메타 정보 |
| `--text-4` | `#A3A3A3` | 플레이스홀더, 비활성, 푸터, 미실행 상태 |
| `--surface` | `#FAFAFA` | 면 카드, 표 래퍼, 사이드 패널 |
| `--surface-2` | `#F5F5F5` | 세그먼트 트랙, 활성 네비 pill, 활성 필터 pill |
| `--border` | `#E5E5E5` | 모든 1px 선 |
| `--bg` | `#FFFFFF` | 페이지 배경 |

**금지:** 파랑·초록·빨강·노랑 등 유채색 전부. 상태색이 필요하다고 느껴지면 §5로 간다.

## 3. 타이포그래피

- 본문 폰트 **Pretendard**, 웨이트 **400 / 500 / 600 세 개만.** Bold(700) 이상 금지.
- 모노스페이스 **JetBrains Mono**는 **라틴 문자·숫자로만 이루어진 텍스트**에만 쓴다: URL, 이메일, `element-12` 같은 ID, 버전(`v1.4`), 빌드 번호(`#44`), 타임스탬프(`9. 2. 15:05`, `01:42`), 에러 메시지(`page.goto: Timeout 10000ms exceeded`), 응답 시간(`893ms`), 신뢰도(`70%`).
  **한 글자라도 한글이 섞이면 Pretendard.** (JetBrains Mono에는 한글이 없어 폰트가 두 개로 쪼개져 보인다. "2026. 9. 2. 오후 3:05", "요소 70개", "~1분"은 Pretendard.)
- 크기 스케일 (이 외의 px 금지):

| 역할 | 크기/행간 | 웨이트 |
|---|---|---|
| 포커스 페이지 제목 (새 분석 플로우) | 32 / 40, letter-spacing -0.02em | 600 |
| 작업 페이지 제목 | 24 / 32, -0.01em | 600 |
| 보고서 섹션 제목 | 18 / 26 | 600 |
| 카드·패널 제목 | 16 / 24 또는 14 / 21 | 600·500 |
| 본문, 인풋, 버튼 | 14 / 21 | 400·500·600(primary 버튼) |
| 라벨, 표 본문, 보조 | 13 / 19 | 400·500 |
| 메타, 표 헤더, 푸터 | 12 / 18 | 400·500 |
| KPI 큰 숫자 | 32 / 38 (목록 페이지 인라인 KPI는 28 / 34), -0.02em, `font-variant-numeric: tabular-nums` | 600 |

- 긴 텍스트는 **꺾지 않는다.** 표 셀·카드 제목·메타는 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`. 설명 문장(description)만 줄바꿈을 허용한다. 줄바꿈이 생기면 텍스트를 줄이거나 열 폭을 조정한다 — 두 줄로 두지 않는다.

## 4. 형태

- **라운드:** pill(999px) = 버튼, 네비 항목, 세그먼트 탭, 필터 pill, 검색·셀렉트 인풋. 12px = 면 카드, 표 래퍼, 사이드 패널. 14px = URL 컴포저와 설정 패널. 10px = 패널 안의 카드. 8px = 카드 안의 텍스트 인풋/셀렉트. 6px = 브랜드 마크만.
- **선:** 1px `--border`. 카드는 **보더 없이 `--surface` 면**이 기본이고, 흰 배경 위에 흰 카드가 필요할 때(패널 안의 카드, 컴포저)만 1px 보더. 강조가 필요한 카드(실패 진단 배너, 판정 대기 카드)는 **1px `--ink` 보더** 하나로 끝낸다.
- **섀도우 없음.** 어떤 요소에도 box-shadow를 쓰지 않는다.
- **버튼:** primary = `--ink` 채움 + 흰 글자 600 + pill, **화면당 정확히 1개**. secondary = 흰 배경 + 1px 보더 + pill + 500. 그 외 액션은 텍스트 링크(13px 500, 뒤에 ` →`). "새로고침·CSV·엑셀 다운로드·다시 실행·수정·초기화"는 절대 primary가 아니다.
- **셀렉트:** 네이티브 화살표 제거(`appearance: none`), 우측 12px 안쪽에 14px 셰브론(stroke 2, `--text-2`), 우측 패딩 36px. 레퍼런스: `M03`, `M05`, `M10`.
- **체크박스:** 16px, `accent-color: var(--ink)`.
- **아이콘:** 원칙적으로 없음. 필요하면 인라인 stroke SVG 14~16px 1개. 아이콘 박스(배경 있는 정사각 아이콘)는 금지.
- **로딩:** 스피너는 §6-C의 사양 하나만 쓴다(28px, 인라인은 16px). 스켈레톤·점 세 개·프로그레스 원형은 쓰지 않는다. 진행률이 있으면 2px `--ink` 선(`M04`).

## 5. 상태 표기 — 색 대신 글리프와 굵기

상태는 항상 `[글리프] [라벨]` 한 덩어리(13px, gap 6px, 글리프는 모노 12px). 새 상태가 생기면 이 표에 먼저 추가한다.

| 상태 | 글리프 | 색 | 웨이트 |
|---|---|---|---|
| 완료 · 성공 · 통과 · 정상 · 안전 | `✓` | `--ink` | 500 |
| **실패 · 오류** | `✕` | `--ink` | **600** (표에서 유일하게 600 → 눈에 띔) |
| 진행 중 · 실행 중 · 확인 중 · 수정 중 | `◌` | `--ink` | 500 |
| 확정 대기 · 검토 필요 · 주의 · 재검증 요청 | `◐` | `--ink` | 500 |
| 대기 · 신규 | `○` | `--text-4` | 400 |
| 미실행 · 건너뜀 · 보류 | `–` | `--text-4` | 400 |

보강 규칙: 실패가 있는 행은 상태 메시지도 `--ink` 500으로 올린다(정상 행은 `--text-2` 400). 실패 보고서 상단에는 진단 한 줄을 `1px --ink` 보더 배너로 놓는다(`M08`). 심각도는 "치명적"만 600, 나머지는 400.

## 6. 레이아웃 패턴

세 종류의 페이지가 있다. 어느 쪽인지 먼저 정한다.

**A. 포커스 페이지** (새 분석 플로우: 진입 → 설정 → 실행 중)
- 콘텐츠 720px 가운데 정렬. 제목 32px 중앙. 진입은 상단 여백 148px, 설정·실행 중은 96px.
- **URL 컴포저**(`M01`): 1px 보더 14px 카드, 안에 모노 URL 인풋(보더 없음) / 하단 행 좌측 세그먼트(기능 QA·UI 점검), 우측 카운터 + primary 버튼. 이 컴포저는 플로우 전체에서 같은 자리에 유지되고, 설정 단계부터는 URL이 고정되고 "변경" 링크만 남는다.
- **설정 패널**(`M02`, `M03`): `--surface` 14px 패널, 안에 2열 흰 카드(제목 14/500 → 메타 12 `--text-4` → 설명 → 컨트롤). 하단에 설정 요약 한 줄 + 순서 한 줄 + primary "이 설정으로 실행". **분석 시작을 누르기 전에는 설정을 보이지 않는다.**
- **실행 중**(`M04`): 단계 리스트. 상태 열 64px 고정, 우측 메타(모노). 2px 진행선. 하단 "취소" 텍스트 링크.
- 진입 화면 하단에 최근 분석 3장(`--surface` 12px 카드, 호스트명 모노).

**B. 작업 페이지** (이력·결함·시스템 상태·보고서)
- 좌우 패딩 120px → 1200px 콘텐츠. 상단 여백 32px. 제목 24px + 옆에 건수(14 `--text-3`) + 아래 설명 한 줄. 우측 상단에 액션 버튼(secondary … primary 순, 최대 2개).
- 블록 간 24px. 보고서는 섹션마다 `1px --border` 상단선 + 32px 패딩, 좌측에 모노 번호(`01`, `02` …), 우측 상단에 섹션 액션.
- **표**(`M05`, `M10`): `--surface` 12px 래퍼 안에 흰 10px 본문. 헤더는 12px `--text-3`, **셀과 같은 x 시작점**(래퍼 패딩 + 행 인셋 = 28px). 행은 세로 12~14px, 행 사이 1px 선, 마지막 행은 선 없음. 열은 CSS grid 고정폭 + 1fr 하나. 상태 열은 최소 112px, 글리프 열은 88px. 행 전체를 링크로 만들 경우 그 안에 다른 링크를 넣지 않는다(중첩 `<a>` 금지) — 액션 열이 있으면 행은 링크가 아니다.
- **KPI 스트립**(`M06~M08`): `--surface` 12px 한 덩어리를 N열로 나누고 열 사이 1px 선. 라벨 13 `--text-3` → 숫자 32/600 → 보조 12 `--text-4`. 카드 4장으로 나누지 않는다.
- **빈 상태**: `1px dashed --border` 12px 박스, 가운데 15/500 제목 + 14 `--text-3` 설명 + secondary 버튼 하나. KPI가 전부 0인 페이지는 KPI를 인라인 텍스트로 줄인다(`M09`).
- **문제 묶음 카드**(`M12`): 1px 보더 12px 카드. 헤더 = 모노 번호 + 제목 16/600 + 심각도 텍스트(높음 600 / 보통 500 / 낮음 `--text-3`) + 우측 우선순위 텍스트(우선 수정 600 / 다음 수정 500 / 개선 권장 `--text-3`). 본문 = `--surface` 3열(발생 이유 / 권장 수정 / 확인 기준, 라벨 12 `--text-4` + 본문 13). 영향 요소는 3열 아래 **디스클로저**(`▶ 영향 요소 N건 보기` 13/500, 펼치면 `▼`)로 열고, 펼친 목록은 요소 카드를 세로로 쌓는다: 카드(1px 보더 10px, 패딩 16) = 제목 14/500 + 설명 13 `--text-2`(우측 12px 발견 화면명) → `--surface` 프레임(200×112 썸네일 + "발견 당시 화면 / 최초 화면 · 새 창에서 크게 보기 →") → 모노 셀렉터 12px → width/height/minimum pill. 레퍼런스에서는 2건만 그리고 "나머지 N건 더 보기 →"로 표시했지만 실제 구현은 전부 펼친다. 하단 판정 행 = 라벨 + pill 셀렉트(미검토 / 수정 필요 / 오탐 / 보류) + pill 메모 인풋 + secondary "저장" — 카드 안에서는 primary를 쓰지 않는다. 결과 페이지엔 primary가 없어도 된다(수행할 다음 행동이 없는 화면).
- **수집 화면 갤러리**(`M12`): 3열 `--surface` 12px 썸네일(200px) + 캡션(이름 좌 / 모노 해상도·위치 우).
- **접기**: 반복 항목은 변경된 것·문제 있는 것만 펼치고 나머지는 "N건 더 보기" 텍스트 링크. 완료된 진행 상태(진행 바, 단계 칩)는 한 줄 텍스트로 접는다.

**C. 인증 페이지** (로그인·처리 중)
- 네비 없음. 400px 단일 컬럼을 화면 정중앙에. 위에서부터 40px 검정 마크(10px 라운드) → 제목 24px → 설명 14px → 폼(라벨 13/500 + 40px 인풋 8px 라운드, 필드 간 16px) → primary 로그인(pill, 전체 폭) → `--surface` 12px 카드로 심사용 계정(라벨 12 `--text-4` / 값 모노 13, 우측 상단 "계정 정보 입력 →" 링크). 마케팅 카피·체크 리스트 패널은 두지 않는다. 푸터는 가운데 정렬 "Probe QA | v1.4 | 이용 안내".
- **폼 검증**(`M00c`, `M00d`): 브라우저 기본 검증 툴팁("이 입력란을 작성하세요")은 쓰지 않는다 — `<form novalidate>` 후 직접 처리. 필드 오류 = 해당 인풋 보더 `--ink` + 인풋 아래 6px에 `✕ 메시지`(12px 500 `--ink`, 글리프 모노 11px) + `aria-invalid="true"`. 메시지는 "○○을 입력하세요." 형태 한 문장. 서버 오류(인증 실패 등) = 버튼 아래 16px에 `role="alert"` 배너: 1px `--ink` 보더 8px 라운드, 패딩 12/14, 좌측 ✕ 글리프, **제목 13/600 한 줄 + 설명 13 `--text-2` 한 줄로 의도적으로 2행** (한 문장을 길게 써서 자동 줄바꿈되게 두지 않는다). 빨간색·핑크 배경은 쓰지 않는다. 같은 패턴을 모든 폼(설정 패널, 판정 폼)에 적용한다.
- **처리 중 오버레이**(`M00b`): 전체 화면 `rgba(255,255,255,0.6)` 딤(블러 없음, 뒤 화면 opacity 0.55), 가운데 280px 흰 카드(1px `--border`, 14px 라운드, 패딩 28/24/24). 스피너 28px: `--border` 원 + `--ink` 1/4 호, stroke 2.5, 0.9s 회전. 아래 제목 14/600 + 설명 13 `--text-2`. 이 오버레이는 로그인뿐 아니라 모든 "요청 처리 중" 상황에 같은 사양으로 쓴다. `role="status" aria-live="polite"`.

공통(A·B): 네비 56px(브랜드 24px 검정 마크 + 이름, 가운데 pill 네비, 우측 모노 이메일 + 로그아웃), 푸터 48px 12px `--text-4`.

## 7-1. 버튼·링크 라벨 규칙

- 형태: **명사 + 동사** ("분석 실행", "PDF 다운로드"). 조사·어미 없음, 마침표 없음, 2~5어절.
- 동사 구분: **시작** = 플로우에 진입(URL 입력 직후), **실행** = 실행기를 실제로 돌림, **다시 실행** = 같은 대상 재실행, **보기** = 화면 이동만, **다운로드** = 파일 저장, **만들기** = 새 항목 생성, **추가** = 기존 목록에 항목 추가.
- 텍스트 링크는 뒤에 ` →`를 붙이고, 버튼에는 붙이지 않는다(primary CTA만 예외로 ` →` 허용: "분석 시작 →").
- 같은 행동은 어느 화면에서든 같은 라벨. 아래 표가 원본이며, 새 라벨이 필요하면 이 표에 먼저 추가한다.

| 행동 | 라벨 | 형태 |
|---|---|---|
| 로그인 | 로그인 | primary |
| 심사 계정 자동 입력 | 심사용 계정으로 채우기 → | 텍스트 링크 |
| 새 분석 플로우 진입 | 분석 시작 → / UI 점검 시작 → | primary (컴포저) |
| 설정 확인 후 실행 | 분석 실행 / UI 점검 실행 | primary (설정 패널) |
| 입력한 URL 바꾸기 | URL 변경 | 텍스트 링크 |
| 실행 중단 | 취소 | 텍스트 링크 |
| 목록 갱신 | 새로고침 | secondary |
| 새 분석으로 이동 | 새 분석 | primary (이력 페이지) |
| 파일 저장 | PDF 다운로드 / CSV 다운로드 / 엑셀 다운로드 | secondary |
| 같은 URL 재분석 | 다시 분석 | primary (완료 보고서) |
| 확정 시나리오 실행 | 확정 시나리오 N개 실행 | primary (확정 대기 보고서) |
| 실패 후 재실행 | 다시 실행 | primary (실행 오류 보고서) / 행 텍스트 링크 |
| 사전 점검 재수행 | 다시 점검 | secondary |
| 시나리오 추가·수정·제외 | 새 시나리오 추가 / 수정 → / 제외 → | secondary / 텍스트 링크 |

| 결과 판정 | 판정 → / 추천 판정 적용 / 판정 저장 | 텍스트 링크 / secondary / primary(카드 내) |
| 결함 등록 | 결함 등록 → | 텍스트 링크 |
| 필터 리셋 | 필터 초기화 | 텍스트 링크 |
| 시스템 상태 재확인 | 상태 다시 확인 | secondary |
| UI 문제 묶음 판정 | 저장 | secondary (카드 내) |
| 근거 화면 확대 | 크게 보기 → | 텍스트 링크 |
| 이동형 링크 | 전체 이력 → / 이전 보고서 보기 → / 실행 기록 보기 → / 실패 테스트 보기 / 검토하고 확정 → / 이전 결과와 비교 → / 결과 검토 → | 텍스트 링크 (빈 상태에서만 secondary) |
| 파일 선택 | PDF 선택 / 이미지 선택 | secondary(소형 32px) |

## 8. 새 화면을 추가할 때의 절차

1. A/B/C 중 어느 레이아웃인지 정한다. 새 분석 플로우의 단계면 A, 로그인·비밀번호 재설정 등 인증이면 C, 그 외 전부 B.
2. §7에서 가장 비슷한 화면을 열어 **그 HTML을 복제해서 시작**한다. 네비·푸터·제목 블록은 그대로 쓴다.
3. 새 상태·심각도·유형이 생기면 §5 표에 먼저 추가하고 글리프를 배정한다. 색을 추가하지 않는다.
4. 반복 데이터는 표, 설정은 카드, 요약 수치는 KPI 스트립. 세 가지 이외의 새 컴포넌트를 만들기 전에 기존 것으로 되는지 먼저 확인한다.
5. 1440×900에서 렌더링해 확인한다: 예상치 못한 줄바꿈 없음, 표 헤더와 셀 x 정렬, 셀렉트 셰브론 안쪽 여백, 한글이 모노로 렌더링되는 곳 없음, primary 버튼 1개.
6. 판단이 필요한 지점(정보를 숨길지, 어떤 상태를 강조할지)은 임의로 정하지 말고 기획자에게 질문으로 넘긴다.

## 8-1. 디자인에 없는 화면을 만들어야 할 때

디자인 레퍼런스(`design/screens/`)에 없는 화면이나 상태를 구현해야 하면 아래 순서를 따른다. 순서를 건너뛰지 않는다.

1. 구현을 시작하기 **전에** 사용자에게 알린다: "이 화면은 디자인에 없습니다. 레퍼런스 `Mxx`를 기준으로 그리겠습니다." 기획자가 먼저 디자인을 만들어 줄 수 있다.
2. `design/screens/`에서 가장 가까운 화면의 HTML을 그대로 복제해서 시작한다. 네비·푸터·제목 블록·표·카드·버튼은 복제한 것만 쓴다.
3. 새 컨테이너(카드, 박스, 배너, 배지)를 추가하려는 순간 멈추고 자문한다: "이 정보가 텍스트 한 줄로 안 되는가?" 텍스트로 되면 텍스트로 한다.
4. 아래 8개 중 하나라도 해당하면 잘못 그린 것이다. 고치기 전엔 PR을 올리지 않는다.
   - 카드 안에 카드가 있다
   - 카드 왼쪽에 색 보더가 있다
   - 완료·성공 상태가 배너나 카드로 남아 있다 (→ 헤더 메타 한 줄)
   - 유채색 배지·pill·텍스트가 있다
   - 필터·툴바가 박스로 감싸져 있다
   - 같은 폼(판정, 메모 등)이 화면에 2개 이상 펼쳐져 있다 (→ 1개만 펼치고 나머지 접기)
   - 반복 항목이 5개 이상 전부 펼쳐져 있다 (→ "N건 보기"로 접기)
   - 버튼에 아이콘이 붙어 있거나, 라벨이 `DESIGN.md §7-1` 표에 없다
5. 1440×900에서 렌더링한 스크린샷을 PR에 첨부하고, "디자인 레퍼런스에 없는 화면"이라고 표시한다. 기획자가 디자인을 확정하기 전까지는 임시 구현이다.
